# 패치 적용 (토핑, `Shaver/Topping.swift`)

이미 가져온 게임에 바뀐 파일만 든 zip(예: 한글 패치)을 덮어쓰고, 언제든 원래대로 되돌린다. 2026-11-14 첫 구현.

## 왜

- 빌드 39 는 "패치만 든 zip" 가져오기를 막기만 했다. 사용자는 PC 에서 덮어쓴 뒤 게임 전체를 다시 zip 으로 묶어야 했다.
- 포켓몬 Z 한글 패치(v6)는 원본 `mkxp.json` 을 같이 넣어서 빌드 39 의 판별(맨 위에 mkxp.json·ini 둘 다 없음)을 빠져나간다.
  그대로 가져오면 `windowTitle` 이 같아 "이미 있는 게임 › 업데이트"로 가고, 업데이트를 누르면 게임 폴더가 패치 파일만 남는다. 이제 막힌다.
- 패치 안내문도 "아이폰 파일 앱은 같은 이름 폴더를 합치지 않고 통째로 갈아치운다"고 경고한다. 빙수가 파일 단위로 합쳐 주면 그 함정이 없다.

## 조사한 패치 (포켓몬 Z 한글 패치 v6, 2026-08-21)

| zip | 크기 | 구조 |

| `…v6_1-galmuri` / `_2-dppt` / `_3-bw` (합본, 글꼴만 다름) | 23MB, 270개 | 최상위 폴더 **없음**. `Audio/SE/…`, `Data/Scripts.rxdata`·`Data/korean.dat`·`Data/Map003…504.rxdata`, `Fonts/*.ttf`(원본 글꼴 이름 8개를 한글 글꼴로 교체 + `kr-*.ttf`), `Graphics/{Battlers,Characters,Icons,Pictures,Titles…}`, `mkxp.json`(원본 배포판 것, vsync 끔), `manifest.json`·`mod.json`(모드 도구 이름표), `번역표/`(jsonl·py 도구), `읽어주세요.txt` |

- 추가판은 합본 위에 덮는다 → 패치는 여러 개가 쌓인다.

## 흐름

1. **들어오는 길** (2026-11-15 업데이트와 하나로 합침 — 사용자: "업데이트랑 패치랑 사람들은 같다고 생각할 것")
   - 게임칩 길게 누르기 › **업데이트**, 게임 정보 › 패치 › **업데이트**: 그 게임을 대상으로 zip 을 고른다. 빙수가 zip 을 보고 정한다.
     - 게임 전체 zip(같은 게임) → 예전 "새 버전으로 업데이트"와 같음: 확인 화면 → 게임 파일 통째로 교체, 저장·설정·표지 유지, 패치 기록은 지움.
     - 바뀐 파일만 든 zip(`looksLikeRGSSPatch`, 또는 엔진을 모르는데 그 게임과 겹침) → 묻지 않고 그 게임의 패치 미리 보기(`Delivery.Stage.patchReady`).
     - 게임 이름(ini·mkxp.json)은 있지만 게임의 일부만 든 zip(`Topping.isPartial`: 게임에 있는 본체 파일 — `Data/System.r*`·`Game.rgss*`·`www/data/System.json` — 이 하나도 없거나, 파일 수가 30% 아래이고 암호화 아카이브도 없음) → 패치로. 통째로 바꾸면 빠진 파일이 사라지기 때문. 대상 없이 게임 추가로 넣었는데 같은 게임이 있을 때도 이 검사를 거쳐 "어느 게임에 적용할까요?"로 간다.
     - 그 게임의 새 버전도, 그 게임에 맞는 패치도 아니면 → "업데이트할 게임과 달라요"(다른 파일 고르기/취소). 예전처럼 패치 zip 을 이유로 막지 않는다.
   - 게임 추가로 패치만 든 zip 을 가져오면 → "패치만 든 zip 이에요 · 어느 게임에 적용할까요?"(겹치는 파일이 있는 게임만, 많은 게임이 위). 주소로 받은 zip 도 같은 길.
   - 미리 보기 화면 제목은 "업데이트", 본문은 "이 패치를 적용할까요? · 게임 전체가 아니라 바뀐 파일만 든 zip 이라 이 게임 파일 위에 덮어써요". 되돌리기는 게임 정보 › **패치 되돌리기** 그대로.
2. **풀기**: `Games/.import-<uuid>/` 에 `SafeUnzip`(경로 탈출·심볼릭 링크·크기·여유 공간 검사). 남은 임시 폴더는 다음 가져오기가 치운다.
3. **맞추기**(`align`): 패치 루트 후보(맨 위, 폴더 하나뿐이면 한 겹씩 안으로) × 게임 기준 후보(게임 폴더, MV·MZ 면 그 루트) 중 점수가 가장 높은 짝.
   이미 있는 파일 = 3점, 부모 폴더가 있는 새 파일 = 1점. 그래서 `Pokemon Z KR/Data/…` 는 한 겹 벗기고, `Data/Scripts.rxdata` 하나뿐인 zip 은 그대로 둔다.
   이름은 게임 쪽 대소문자로 맞춘다(`data/scripts.rxdata` → `Data/Scripts.rxdata`). 0점이면 "겹치는 곳이 없어요"로 거절.
4. **미리 보기**: 패치 이름(`mod.json`/`manifest.json` 의 name, 없으면 zip 이름), 바꿀 파일 수·새 파일 수·크기, 펼쳐 보는 파일 목록(바꿈/새로), 건너뛸 파일 수.
   알림: 패치의 `mkxp.json` 이 저장 폴더 이름(`dataPathApp`)을 바꾸면 경고, exe·dll 이 들어 있으면 "넣어 둘 뿐 실행하지 않아요".
5. **적용**: 켜 둔 게임이면 닫고, `Toppings/<게임 id>/<순번>/record.json` 을 먼저 쓴 다음 파일마다 덮어쓸 원본을 `originals/` 로 **옮기고**(같은 볼륨 이름 바꾸기, 복사 없음) 패치 파일을 제자리로 옮긴다. 도중에 실패하면 그때까지 한 것을 되돌린다.
6. **게임 정보**: 적용한 패치를 최근 것부터 이름·날짜·바꾼 수로 보여 주고, **패치 되돌리기**는 마지막 것부터 하나씩(새 파일·새 폴더 지우고 원본 제자리).
7. **업데이트·삭제**: 게임 파일이 통째로 바뀌면(게임 전체 zip 으로 업데이트) 또는 게임을 지우면 그 게임의 패치 기록·원본을 지운다(`Topping.forget`).

## 지키는 것 (PLAN 8.2)

- 게임 폴더 밖에 쓰지 않는다: 경로 조각마다 `..`·`.`·`/`·`\`·`:`·제어 문자 거절, 가는 길의 폴더가 링크면 거절, 마지막에 게임 폴더 안인지 다시 확인. 기록 파일(`record.json`)을 조작해도 되돌리기가 같은 검사를 거친다.
- 저장 데이터를 건드리지 않는다: 저장은 `Documents/Saves` 라 애초에 대상이 아니고, 게임 폴더의 PC 저장 모양(`Save01.rvdata2`, `file1.rpgsave`, 맨 위 `Game*.rxdata`)과 빙수 영수증 `bingsu.json` 은 패치에 있어도 건너뛴다.
- 실행하지 않는다: exe·dll·py 는 파일로 놓을 뿐이다. 빙수는 가져온 어떤 파일도 실행하지 않는다(RGSS 스크립트는 원래대로 엔진이 읽는다 — 패치의 `Scripts.rxdata` 도 게임 스크립트라 같은 위험 등급, PLAN 빌드 46 의 파일 접근 제한 대상).
- 백업은 `Application Support/Toppings/` (게임 폴더 밖, 게임 크기·목록에 섞이지 않음, iCloud·Files 에 안 보임).

## 패치만 든 zip 판별 (`Topping.looksLikeRGSSPatch`)

RPG Maker 로 보이는데 맨 위에 ini 가 없고, (mkxp.json 도 없거나 / 게임 본체 = `Data/System.rxdata|rvdata|rvdata2` 와 암호화 아카이브가 없음).
엔진을 모르는 zip 이라도 가져온 게임의 파일과 겹치면 패치로 보고 게임을 묻는다(MV·MZ 의 `www/data` 만 든 zip 등).

## 이 게임용 패치인지 (지문 검사, 2026-11-15)

경고만 하고 막지 않는다. 미리 보기 맨 위 주황 상자 "이 게임용 패치가 아닌 것 같아요" + 이유 한 줄, 아래에 "그래도 적용할 수 있고, 게임 정보 › 패치 되돌리기로 원래대로 돌릴 수 있어요."

- **지문이 있으면** (modkit `manifest.json`: `modkit_manifest` + `files {경로: [크기, CRC32]}`): 패치가 바꾸지 않는 원본 파일의 크기를 게임 폴더와 비교. 20개 이상 비교했는데 같은 게 70% 미만이면 경고. `exclude` 는 대소문자 무시 fnmatch. 실측 — 한글 패치 → Z 18863/18872 같음, → 어나더 레드 28/18872.
- **지문이 없으면**: (1) 패치 항목 10개 이상인데 게임에 있는 파일이 30% 미만, (2) 바꿀 파일 10개 이상인데 바이트까지 같은 게 5% 미만이고 크기 25% 안쪽인 것도 30% 미만이면 경고. (3) 둘 다 `Game.ini` 를 가졌는데 Title 이 다르면 경고. 실측 — Patch/→AR 같음 286·가까움 114/146(경고 없음), Patch/→Z 같음 1·가까움 57/418(경고), ZKR→AR 225 중 7개만 있음(경고).
- 게임 고르기 목록(여러 게임과 겹칠 때)은 각 게임으로 계획을 세워 보고, 안 맞는 게임을 뒤로 보내고 " · 이 게임용이 아닌 것 같아요" 를 붙인다.

## 패치 뒤 게임이 시작될지 (스크립트 검사)

같은 상자에 "이 패치를 적용하면 게임이 시작되지 않을 수 있어요" + 이유. 역시 막지 않는다.
- 새 `Scripts.rxdata|rvdata|rvdata2` 의 머리가 Marshal(04 08)이 아니면 경고. 그 밖에 읽다 실패하면 말하지 않는다(헛경고 방지).
- 스크립트가 신형 Ruby 문법인데 패치 뒤 `mkxp.json`·Ruby 3 DLL 이 없어 구형 Ruby 로 켜질 상황이면 경고.
- 고친 것: `RGSSProbe` 의 MarshalReader 가 큰 정수(`l`)를 몰라 어나더 레드 `Scripts.rxdata` 를 못 읽었다 → 지원(이 때문에 AR 의 Ruby 판별도 바뀔 수 있음).

## Ruby 선택 기록

적용 전후 `RubyProfile.detect` 결과를 `record.json` 의 `rubyBefore`·`rubyAfter`("18 legacy"/"31 modern")에 남기고 로그에 "Ruby X → Y". 다르면 진단 정보(이 게임 설정 맨 아래)에 "패치 뒤 Ruby: <패치 이름>: Ruby 1.8 · legacy → Ruby 3.1 · modern". 미리 보기에는 안 보인다.
- iPad 에서 Z + 한글 패치: 기록 18 legacy → 31 modern, 진단 "Ruby 자동 판별: Ruby 3.1". 되돌린 뒤 진단은 "Ruby 1.8 · 문법 legacy", 크기 932.3MB → 900.1MB, 패치 뒤 Ruby 줄 사라짐 — 스크립트 판단 캐시(Scripts 크기·수정 시각 키)가 되돌리기 뒤에도 다시 판단한다.

## 확인 (`BINGSU_SELFTEST=1` → `[Topping] selftest 38/38 OK`)

한 겹 벗기기·`Data/` 하나뿐인 zip·대소문자 맞추기·영수증/저장 파일 건너뛰기·두 패치 쌓고 거꾸로 되돌리기(바이트 비교)·새 파일·새 폴더 지우기·겹침 없음 거절·게임 폴더 안 링크 거절(밖에 안 씀)·조작된 기록의 경로 탈출 거절·일부만 든 zip 판별·지문 없는 맞는/틀린/적은 패치·지문(manifest) 맞음/틀림·깨진 Scripts 경고.

개발용 환경 변수: `BINGSU_PATCH="<게임 id>|<zip 경로>"`(그 게임의 패치 화면을 그 zip 으로), `BINGSU_PATCH_APPLY=1`(미리 보기 없이 바로 적용), `BINGSU_PATCH_AGAIN=1`(이미 패치가 있어도 다시).

## 남은 것

- 실기기 미확인(iPhone 16·iPad Air 5). 큰 패치의 미리 보기 목록은 300개까지만 그린다.
- 같은 패치를 두 번 적용하면 두 번째 원본 = 첫 패치 파일이라 하나씩 되돌리면 맞게 돌아온다(쌓기 규칙). "모두 되돌리기"는 없다.
- 켜 둔 RPG Maker 게임은 한 프로세스에 한 번만 켜져서, 패치 뒤 바로 다시 하려면 빙수를 다시 열어야 한다(업데이트와 같음).
- Electron 게임(asar 안 파일)과 암호화 아카이브(`Game.rgssad`) 안 파일을 바꾸는 패치는 대상이 아니다.
