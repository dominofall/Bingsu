# RPG Maker 게임의 파일·네트워크 울타리 (빌드 46, 2026-11-15)

## 무엇이 문제였나

RPG Maker XP·VX·VX Ace 게임(놋그릇 = mkxp-z)은 게임 안의 Ruby 스크립트를 **빙수 앱 프로세스 안에서** 돌린다.
2026-11-04 시뮬레이터 측정에서 가져온 게임 스크립트가 할 수 있던 일:

- 다른 게임의 저장 파일 목록 보기·읽기·쓰기
- 빙수 설정(`Library/Preferences`, `Documents/Prefs`) 읽기
- 웹 게임 로그인 정보가 든 `Library/WebKit` 폴더 열기 (포켓로그 계정 등)
- 자기 저장 폴더 밖에 파일 쓰기
- 소켓·HTTP 로 밖에 보내기

`BingsuSaves`(Ruby 로 파일 이름을 저장 폴더로 돌리는 preload)는 편의 기능이지 경계가 아니다. Ruby 수준의 감싸기는 게임 스크립트가 피해 갈 수 있다.

## 어떻게 막나

엔진 프레임워크 안에 **울타리(`BingsuApp/BrassBowl/fence.c`)** 를 넣었다. 엔진·Ruby·SDL·PhysFS 는 프레임워크 안에 정적으로 링크되므로,
그 안에서 부르는 libc 함수(`open`, `stat`, `opendir`, `rename`, `unlink`, `socket`, `getaddrinfo`, `syscall` ...)를 같은 이름으로 정의하면
링커가 프레임워크 안의 호출을 전부 울타리로 묶는다. 이 이름들은 내보내지 않으므로(`brassbowl.exports` 는 `mkxp_*` 만) **빙수 앱 본체와 시스템 프레임워크의 호출은 그대로**다.
Ruby 판(1.8·1.9·3.1)에 상관없이 같은 길을 지난다. 링크 뒤 `nm -u` 에 감싼 이름이 남지 않는지로 확인한다.

빙수(`BrassBowlEngine.raiseFence`)가 게임을 켜기 직전에 폴더를 알려 주고 켠다:

| 구분 | 폴더 |
|---|---|
| 쓰기(읽기 포함) | 그 게임 폴더, 그 게임 저장 폴더, 임시 폴더(빙수 preload 스크립트·소리 크기 파일), 진단 기록 파일 1개, 엔진이 저장 폴더 이름 뒤에 붙여 쓰는 `keybindings.mkxp1~3` |
| 읽기만 | 사운드폰트, RTP 폴더 |
| 코드 | 앱 번들 (엔진 Ruby 표준 라이브러리·글꼴). `dlopen` 은 여기와 시스템만 |
| 보호 구역 | 앱 데이터 컨테이너 전체와 같은 사용자의 다른 컨테이너(앱 그룹 등)를 품은 위 폴더 |

규칙:
- 쓰기·지우기·이름 바꾸기·폴더 만들기는 쓰기 폴더 안에서만
- 읽기·목록은 보호 구역 안이면 허용 폴더만. 보호 구역 밖(시스템 파일)은 그대로 (iOS 샌드박스가 따로 막는다)
- `stat`·`access` 처럼 있는지만 보는 것은 허용 폴더의 **조상 폴더 자체**도 허용 (PhysFS 가 시작할 때 집 폴더를 stat 한다). 조상 폴더의 목록·내용은 막힘
- 링크·심볼릭 링크 만들기, `chroot`, 프로세스 실행(`fork`·`execve`·`posix_spawnp`·`popen`), `syscall`·`__syscall`(Ruby 1.9) 은 항상 막음
- 이미 열린 파일 번호를 집는 길(`IO.new(fd)`, `IO.for_fd`)은 `fcntl(F_GETFL)`·`fstat` 에서 그 번호의 실제 경로를 보고 막음
- 네트워크: 이 게임 설정 › "온라인 접속 허용" 을 끄면 `socket`·`getaddrinfo`·`gethostbyname` 을 막음. 엔진 자체 설정(`networkEnabled`)이 먼저 막고, 울타리는 그 뒤의 안전망
- 거부는 `EACCES`(번호는 `EBADF`, 실행은 `EPERM`). 게임에는 파일이 없거나 권한이 없는 것으로 보인다. 로그 `[BrassBowl] fence deny <함수> <경로>` (50줄까지)

울타리가 없는 옛 프레임워크면 게임을 켜지 않는다("게임 실행기가 맞지 않아요"). 막지 못한 채로 돌리지 않기 위해서다.

## 확인 (시뮬레이터, DEBUG, 2026-11-15)

개발용 `BINGSU_FENCE_PROBE=1` 이면 시험 Ruby 스크립트가 preload 맨 끝에 붙어 결과를 임시 폴더 `bingsu-fence-probe.txt` 에 쓴다.

| 게임 | Ruby | 자기 폴더·저장 | 다른 게임 저장·설정·WebKit·위로 빠지기·밖에 쓰기 | 심볼릭 링크·실행·syscall | 시스템 파일 읽기 |
|---|---|---|---|---|---|
| 포켓몬 Z (iPhone) | 3.1 | 됨 | 막힘 | 막힘 | 됨 |
| 포켓몬 어나더 레드 (iPhone) | 3.1, 1.8 강제 | 됨 | 막힘 | 막힘 | 됨 |
| The Witch's House (iPad) | 1.8 | 됨 | 막힘 | 막힘 | 됨 |
| 미노와 전설의 빙수 (iPad, 빙수 시험 게임) | 1.9 | 됨 | 막힘 | 막힘 (처음엔 `__syscall` 이 새어 고침) | 됨 |

- 게임 자신의 저장 길: 미노에서 게임의 `SaveFile.write`·`exist?`·`read` → 저장 폴더에 `Save01.rvdata2`, 다시 읽기 됨
- 네 게임을 시험 스크립트 없이 켰을 때 거부 0건, 첫 화면 정상 (포켓몬 Z 는 울타리를 끈 실행과 같은 화면)
- 온라인 끔: Ruby 3.1 은 엔진 설정이 먼저 `ENETDOWN`. 1.8·1.9 는 엔진이 소켓을 빈 껍데기(`IOS::NullStub`)로 바꿔 실제 통신이 없음.
  `BINGSU_FENCE_NET_OFF=1`(엔진 설정은 켠 채 울타리만 끔)로 Ruby 3.1 에서 울타리가 `getaddrinfo`·`socket` 을 직접 막는 것도 확인
- 처음 켰을 때 막혀서 고친 것: 엔진의 `keybindings.mkxp1` 쓰기(저장 폴더 이름 뒤에 '/' 없이 붙임), PhysFS 시작 때 집 폴더 stat

## 한계

- 허용 폴더 안의 심볼릭 링크는 글자만 보고 판단한다. 가져오기가 심볼릭 링크를 거부하고 게임은 새로 만들 수 없으므로 실제로는 생기지 않는다
- 임시 폴더 전체를 쓰기 허용한다. 빙수 preload 스크립트도 여기 있어 게임이 덮어쓸 수 있지만, 실행할 때마다 새로 쓰므로 그 실행 안에서만 의미가 있다
- 프레임워크 밖(Foundation 등)을 거쳐 파일에 닿는 엔진 코드는 대상이 아니다. 게임 스크립트가 고를 수 있는 길이 아니다(`fiddle`·`dl`·`ffi` 는 들어 있지 않음)
- 메모리를 직접 건드리는 길(엔진·Ruby 의 메모리 버그를 이용)은 막지 못한다. 이건 모든 앱의 스크립트 엔진 공통 한계다
- **실기기에서는 아직 확인하지 않았다.** 다음 업로드 뒤 TestFlight 기기에서 같은 시험(디버그 빌드)을 돌릴 것
