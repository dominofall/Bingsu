# 키 설정 (컨트롤러·하드웨어 키보드 키 매핑)

2026-11-14. 다음 외부 테스트 빌드에 들어갈 기능(사용자). 코드: `Spoon/KeyMap.swift`(모델·저장), `Spoon/HardKeys.swift`(하드웨어 키보드·"누르세요"), `Kitchen/KeyMapView.swift`(화면), `Spoon/KeyMapSelfTest.swift`(자가 테스트).

## 입력 경로 (바꾸기 전)

| 입력 | 길 |
|---|---|
| 가상 패드(`Spoon`) | `SpoonController.press` → `CutlerySet`(게임별 표) → 키보드 게임은 `KeyboardEvent.code`(웹: `__bingsu.key`, RPG Maker: `BrassKeys.scancode` → `mkxp_injectKeyEvent`), 패드 게임은 가상 Gamepad(`__bingsu.pad`) |
| 실제 컨트롤러(`LongSpoon`) | GameController `valueChangedHandler` → 가상 패드와 같은 `SpoonController` |
| 하드웨어 키보드 · RPG Maker | SDL 이 `GCKeyboard.keyChangedHandler` 하나로 받아 바로 게임에 (빙수를 거치지 않음) |
| 하드웨어 키보드 · 웹 게임 | WKWebView 가 DOM 키 이벤트로 바로 받음 |
| 글자 입력(빌드 42 `HardKeyText`) | `GCKeyboard.keyChangedHandler` 를 **통째로 바꿔 끼움** |

빌드 42 의 문제(이번에 같이 고침): `HardKeyText` 가 SDL 의 처리기를 덮어써서 글자 입력 중 Enter·Esc·방향키가 게임에 안 가고, 끝날 때 처리기를 nil 로 비워 그 뒤 하드웨어 키보드가 RPG Maker 게임에 전혀 안 들어간다. 이제 `HardKeys` 한곳만 처리기를 만지고(감싸기), `HardKeyText` 는 거기서 키를 받아 간다.

## 설계

- **컨트롤러**: 실제 버튼 16개(A·B·X·Y·LB·RB·LT·RT·보기·메뉴·L3·R3·십자키 넷)마다 할 일 = 게임 버튼(가상 패드 버튼) · 키보드 키 · 없음. 기본은 같은 버튼. 게임 버튼끼리는 **자리 바꾸기**(X 를 '확인'으로 하면 A 가 X 가 하던 일)라 어느 기능도 버튼을 잃지 않는다. 홈 버튼은 늘 일시정지, 스틱 움직임은 그대로 이동(스틱 누르기 L3·R3 만 바꿈). 일시정지 화면의 컨트롤러 조작은 바꾸지 않은 실제 버튼 그대로(설정을 잘못해도 메뉴는 늘 움직인다).
- **하드웨어 키보드**(2026-11-14 사용자 요청으로 다시 만듦): 게임 버튼(컨트롤러 입력) 16개를 목록으로 보이고, 줄마다 누르는 키보드 키를 하나 지정한다. 키보드로 받는 게임(RPG Maker·일부 웹 게임)은 게임이 원래 쓰는 키(XP: 확인 C, 취소 X, 메뉴 Z, 방향키)가 이미 있으므로 그 키를 회색으로 보인다. 키를 지정하면 그 줄의 원래 키를 **대신한다**: 원래 키는 꺼지고(`KeyMap.gameKeys`, 게임마다 CutlerySet 의 원래 키로 계산) 지정한 키만 보인다. 예: WASD + J K 에서 C·방향키는 아무 일도 안 하고 J 가 확인. 다른 일로 직접 바꾼 원래 키(WASD 의 A·S·D)는 그 일을 한다. 같은 원래 키를 쓰는 버튼이 여럿이면 모두 지정됐을 때만 끈다. 가상 패드·글자 입력 화면은 영향 없음. 게임이 안 쓰는 버튼·패드로만 받는 게임은 "지정되지 않음", 게임 없이(설정) 열면 "게임 기본 키". 게임에 보내는 키 "(C)"는 키보드 탭 이름에서 뺀다(지정한 키와 헷갈려서). 줄을 누르고 키를 누르면 그 줄의 키가 바뀌고, 그 키가 다른 줄에 있었으면 옮겨 온다. 맨 위 "기본 배치 프로필"은 게임 기본(지정한 키 모두 지움, 게임 원래 키 그대로) · WASD + J K(`KeyProfile`). "방향키 + Z X"는 게임 기본과 거의 같아(방향키·X 같고 Z·Enter 만 다름) 헷갈려서 뺐다. 누르면 목록 전체가 그 배치로 바뀐다. 프로필의 키는 빙수가 먼저 받아 게임 버튼으로 바꾸고(J → A → XP 에는 C), 프로필에 없는 키는 그대로 게임에 간다. 지정하지 않은 키는 지금처럼 원래대로 게임에 간다. 모델은 여전히 키 → 대상이라 다른 키·없음 대상도 읽고 "그 밖의 키"에 보인다(새로 만들지는 않음).
  - RPG Maker: SDL 의 GCKeyboard 처리기를 감싸 바뀐 키만 가로채고 나머지는 SDL 로. 엔진 소스는 고치지 않는다.
  - 웹 게임: 주입 스크립트(`BowlScripts.hardKeyGuard`)가 바뀐 키의 진짜 입력(isTrusted)만 막고 `hardkey` 메시지로 넘긴다. 빙수가 만든 키는 건드리지 않는다. 메시지 값은 키 표에 있는 것만 받는다.
  - 결과는 가상 패드와 같은 길(`SpoonController.press` / `setDirectKey`).
- **글자 입력 중에는 바꾸지 않는다**: RPG Maker 는 엔진의 글자 요청(`textInputActive`)·게임 키보드가 떠 있을 때·두벌식 이름 입력 화면·`HardKeyText` 동안 그대로 통과. 웹 게임은 글자 칸(input·textarea·contenteditable)에 커서가 있으면 막지 않는다. 누른 채 글자 화면이 열려도 뗌은 같은 대상으로 보낸다.
- **범위·저장**: 전역 = UserDefaults `keys.map`(기기마다). 게임별 = `DishPrefs.keyMap`(`Documents/Prefs/<id>.json`, iCloud 동기화). 패드 설정처럼 통째 덮어쓰기(nil = 전역), "모든 게임에 적용"도 같다. **게임을 지우면 그 게임의 키 설정도 함께 지워진다**(설정 파일과 같이). 전역 값은 남는다. 형식 `{"v":1,"pad":{"x":"pad:a"},"keys":{"KeyW":"pad:up"}}`, 다른 기기에서 온 값은 항목별로 검사해 모르는 버튼·키는 버린다(키 코드가 웹뷰 스크립트에 들어가므로 표에 있는 키만).
- **화면** `키 설정`: "컨트롤러·키보드" 화면(`Kitchen/InputView.swift`: 연결된 기기·키 설정·애플워치·iPhone 컨트롤러·패드 연결 안내를 한곳에, 2026-11-14 사용자 결정) 안에 있다. 이 화면은 설정 › 컨트롤러·키보드, 이 게임 설정 › 컨트롤러·키보드, 일시정지 › 컨트롤러·키보드(맨 아래, 컨트롤러나 키보드가 연결됐을 때만, 컨트롤러로도 열림) 한 줄로 연다. 진동은 폰과 같이 쓰는 값이라 설정 › 소리·진동에 둔다. 키 설정 줄 오른쪽에는 "기본"·프로필 이름·"바꿈"(게임 설정에서는 "이 게임만"/"모든 게임 설정"). 위의 "컨트롤러 | 키보드" 나눔. 줄을 누르면 "컨트롤러 버튼을 누르세요"/"바꿀 키보드 키를 누르세요" — 실제 버튼·키를 60Hz 로 읽어 잡는다(처리기를 바꿔 끼우지 않음). 기다리는 동안 게임에는 보내지 않는다. 대체 목록은 두지 않는다(설정은 기기를 연결한 채 하므로, 2026-11-14 사용자 결정). 연결된 것이 없으면 "연결된 컨트롤러가 없어요 · 연결하면 바로 받아요"를 보이고 계속 기다린다(연결 상태는 기다리는 동안 계속 살핀다). 일시정지에서 연 키 설정은 컨트롤러 B·홈 버튼으로 닫힌다(그 화면 안의 조작은 터치). 겹치는 배치(누를 버튼이 없는 기능, 같은 일을 하는 버튼·키 둘, 바뀐 키를 다시 대상으로 쓴 것)는 위에 주황 경고. "컨트롤러 재설정"·"키보드 재설정". "누르세요" 창은 기다리는 동안 퍼지는 고리와 "입력을 받고 있어요"를 보이고, 잡으면 "X 버튼을 받았어요"를 잠깐 보인 뒤 닫히며 바뀐 줄이 잠깐 밝아진다.
- **잡는 키 표**(`KeyCatalog`): 글자·숫자·Enter·Esc·Space·Tab·⌫·기호·F1~F12·편집 키·방향키·숫자패드·Ctrl·Shift·왼쪽 Alt. Caps Lock·한/영·오른쪽 Alt·⌘ 는 뺐다(한/영 전환과 iOS 단축키).

- **GCKeyboard 가 없을 때**(시뮬레이터, 일부 기기): SDL 은 UIKit `pressesBegan/Ended/Cancelled` 로 키를 받는다. 그래서 `SDL_uikitview` 의 그 세 메서드도 감싸(`installPressHook`, 런타임 교체) `GCKeyboard.coalesced == nil` 일 때만 바뀐 키를 빼서 처리하고 나머지는 SDL 로 넘긴다.
- 저장 위치 확인: 전역 값은 앱 컨테이너 `Library/Preferences/com.minwoo.bingsu.plist` 의 `keys.map`(시뮬레이터에서 `simctl spawn … defaults read` 는 다른 곳을 읽어 옛 값이 보인다. 파일을 직접 읽을 것). 게임별 값은 `Documents/Prefs/<safeName>.json` 의 `keyMap`.

## 확인

- 자가 테스트 `BINGSU_KEYMAPTEST=1`(또는 `BINGSU_SELFTEST=1`) → `[Keys] selftest ok`.
- 하드웨어 키 로그 `BINGSU_KEYDEBUG=1` → `[Keys] hardware KeyW → pad:up true`.
- 하드웨어 키 흉내 `BINGSU_HARDKEYS="초:코드,…"`(Debug, 예 `"6:KeyJ,8:KeyS"`): 그 시각에 키를 누르고 0.15초 뒤 뗀다. RPG Maker 는 감싼 처리기의 길 고르기부터, 웹 게임은 `hardkey` 메시지부터 탄다.
- 시뮬레이터 한계: 시뮬레이터 도구의 키 입력은 SDL 뷰·WKWebView DOM 에 닿지 않는다(바꾸지 않은 Enter 도 안 감). 그래서 OS → 처리기 구간과 진짜 컨트롤러는 실기기에서만 확인된다.

### 2026-11-14 시뮬레이터 결과 (iPhone 17 Pro, iPad Pro 13)

- 자가 테스트 통과.
- 웹 게임(빙수 한 그릇): Enter → A 는 `KeyZ` 로, ArrowDown → ArrowUp 으로 게임에 들어감.
- RPG Maker XP(Wishing Star): J → A(`KeyC`)로 타이틀 넘어감, S → ↓ 로 메뉴 커서 이동.
- 화면: 일시정지 › 키 설정 시트, "버튼을 누르세요", X 를 확인으로 하면 A·X 자리 바뀜, 이 게임만 켜면 게임 파일에만 저장되고 전역은 그대로, WASD 한 번에 넣기, 가로 화면, iPad 설정 › 키 설정.

### 글자 입력과 바꾼 키

W 를 ↑ 로 바꿔도 이름 입력에서는 w 가 들어간다. 글자 입력 화면(엔진의 글자 요청·게임 키보드·두벌식 이름 입력·HardKeyText, 웹은 글자 칸 커서)에서는 바꾼 키를 쓰지 않고 원래 키를 그대로 보내기 때문. 예외: 글자 요청 없이 키를 하나씩 읽어 자기만의 이름 입력 화면을 만든 게임에서는 W 가 계속 ↑ 라 쓸 수 없다. 이런 게임은 그 게임만 키 설정을 끄거나 다른 키를 쓰면 된다.

### 실기기에서 확인할 것

1. BT 키보드 + RPG Maker: 바꾼 키, 바꾸지 않은 키, 이름 입력(Enter·Esc) 중 그대로 통과, 입력 끝난 뒤에도 키보드가 계속 먹는지(빌드 42 회귀).
2. 웹 게임: 진짜 키가 막히고 바뀐 대로 가는지, 글자 칸 입력은 막히지 않는지.
3. 컨트롤러: 자리 바꾸기·키보드 키·없음, 일시정지 메뉴는 원래 버튼 그대로.
4. 일시정지에서 연 키 설정이 B·홈으로 닫히는지.
5. "누르세요"에서 실제 버튼·키로 잡히는지.
6. 게임 중 키보드를 끊었다 다시 연결해도 매핑이 살아 있는지.
