# 터치 조작 (웹 계열 2차) — 구현 명세

2026-11-11 결정. 전체 계획은 [`compat-plan.md`](compat-plan.md) §5, 앞 단계는 [`IMPLEMENTATION-electron.md`](IMPLEMENTATION-electron.md)(빌드 37, "2차로 넘길 불편한 점" 포함). 구현 세션(Opus, 워크트리)용 명세다. 명세와 다르게 해야 하면 이 파일 끝 "구현 기록"에 이유와 함께 적는다.

**목표:** PC 에서 마우스와 키보드로 하는 게임을 손가락만으로 불편 없이 한다. 마우스를 연결하지 않고, 화면에 커서도 그리지 않는다. 손가락이 닿은 자리가 곧 마우스 자리다. 첫 대상은 운빨던전. 끝났다는 기준은 §12.

이 기능이 들어가는 빌드 38 은 **외부 테스터에게 나가는 빌드**다. 처음 쓰는 사람이 설명 없이 쓸 수 있어야 한다.

## 0. 원칙

- **게임 이름으로 분기하지 않는다.** 운빨던전은 첫 시험 대상일 뿐이다. 운빨던전에만 필요한 보정이 나오면 코드에 넣지 말고 "구현 기록"에 적는다.
- **켜는 대상은 새 모양 Electron 게임(`dish.isRedBean`)뿐.** 계층 자체는 Electron 과 무관한 공용 스크립트로 만든다(다음 단계에서 다른 로컬 웹 게임에도 켤 수 있게). 레조넌스·MV·MZ·웹 주소 게임·RPG Maker 게임은 스크립트가 아예 들어가지 않아야 하고, `SpoonSelfTest`·`IglooSelfTest`·`GreenTeaSelfTest`·`RedBeanSelfTest` 가 그대로 통과해야 한다.
- **조작 방식(`inputStyle`)과 상관없이 켠다.** PC 에서는 패드 게임 화면도 마우스로 누를 수 있다. 방식이 정하는 것은 셋뿐이다: 가상 패드를 처음에 보일지, 게임이 화면을 채울지, 키보드 키를 처음에 보일지.
- **게임이 스스로 듣는 포인터 이벤트는 건드리지 않는다.** 손가락은 WebKit 이 `pointerdown`·`pointermove`·`pointerup`(pointerType `touch`)으로 실시간으로 보낸다. 운빨던전의 카드 끌기·지도 끌기는 이 길로 이미 된다. 우리가 채우는 것은 **마우스 이벤트, 가리키기, 키보드**다. 오른쪽 클릭·휠·확대는 하지 않는다(§13).
- **진짜 마우스·트랙패드(iPad)는 그대로 통과**한다. 변환은 손가락과 펜에만 한다.
- **PC 브라우저의 규칙을 따른다.** 이벤트 순서, `detail`, `preventDefault` 의 뜻을 PC 와 같게 한다. 모르는 것은 추측하지 말고 PC 브라우저(맥의 Chrome·Safari)에서 같은 시험용 화면으로 확인한다.
- 보안 경계는 37 그대로다(쓰기는 그 게임의 `userData/` 한정). 새 메시지 통로를 만들면 받는 값은 네이티브에서 검증한다(유한한 수인지, 범위, 글자 길이). 게임 코드는 믿지 않는다.
- 화면 문구는 평범한 한국어다. **"포인터 방식"이라는 말은 화면에 쓰지 않는다**(사용자 결정: "터치 조작"). 코드 이름은 빙수 테마, 주석·커밋·보고는 한국어, 엔진 이름은 화면에 보이지 않는다.
- 코드는 직접 쓴다. 다른 프로젝트의 터치·끌어다 놓기 폴리필을 옮기지 않는다.

| 개념 | 코드 (제안, 바꿔도 됨) |
|---|---|
| 터치 → 마우스 변환, `:hover`, 말풍선, 끌어다 놓기 (문서 시작 스크립트) | `Bowl/BowlScripts+Straw.swift` 의 `strawShim` (빨대 = 콕 찍는 것) |
| 키보드 키 줄 | `Spoon/KeyStrip.swift` |
| 게임이 듣는 키 목록 | `RedBeanProbe` 에 더함 → `ElectronInfo.keys`, `bingsu.json` 의 `electron.keys` |
| 게임별 설정 | `DishPrefs` 에 `inputStyle`·`keyStrip` (예전 파일에 없으면 nil = 자동) |
| 자가 테스트 | `Bowl/StrawSelfTest.swift` (`BINGSU_SELFTEST=1` 에 추가) |
| 시험용 화면 | `tools/compat-fixtures/touch-lab/` |

## 1. 먼저 확인할 것 (0단계)

본 구현 전에 시뮬레이터 웹뷰에서 확인하고 결과를 "구현 기록"에 적는다. 결과에 따라 설계의 "대비책"을 고른다. 시험용 화면(§11)을 먼저 만들어 여기서 쓴다.

1. **WebKit 이 탭 뒤에 만드는 마우스 이벤트를 막을 수 있는가.** WebKit 은 탭이 끝난 뒤 `mouseover`·`mousemove`·`mousedown`·`mouseup`·`click` 을 한꺼번에 만든다. `window` 의 capture 단계에서 `isTrusted` 이고 직전 포인터 종류가 `touch`·`pen` 인 것을 `stopImmediatePropagation` 하면 게임이 듣지 못하는가. 그렇게 하면 **"첫 탭은 가리키기만 되고 둘째 탭이 클릭"** 버릇(`mouseenter`·`mouseover` 처리기가 화면을 바꾸면 WebKit 이 click 을 내지 않는 규칙)이 사라지는가. 안 되면 대비책: `touchend` 에서 `preventDefault`.
2. **직접 만든 `click` 안에서 사용자 동작이 필요한 일이 되는가.** `touchend`·`pointerup` 처리기 안에서 `dispatchEvent` 로 보낸 click 에서 `audio.play()`, `navigator.clipboard.writeText`, `<input type=file>.click()`, 37 의 "사이트 열기" 대화상자가 되는지.
3. **입력 칸.** `<input>`·`<textarea>`·`<select>` 를 탭하면 키보드·선택기가 뜨는가(§2.4 통과 목록). 키보드가 뜰 때 게임 화면이 밀리거나 `innerHeight` 가 바뀌는가.
4. **안쪽 스크롤.** `overflow: auto` 영역이 한 손가락으로 스크롤되는가(웹뷰 바깥 스크롤은 꺼져 있다). 스크롤이 시작될 때 `pointercancel` 이 오는가.
5. **길게 누를 때 iOS 가 끼어드는 것.** 글자 선택·돋보기, 콜아웃, 링크 미리보기, 그림 끌어올리기(iPad 의 drag lift). 37 의 `fullscreenCSS`(`user-select`·`touch-callout` 끔)가 새 모양 게임에도 들어가는지 확인하고, 남는 것은 끈다(`-webkit-user-drag: none`, 웹뷰의 `UIDragInteraction` 끄기 등).
6. **네이티브 제스처 인식기.** (§5·§6 을 지워 지금은 쓰지 않는다. 결과는 기록으로만 남김) 웹뷰(또는 그 그릇 뷰)에 붙인 두 손가락 핀치·끌기·탭 인식기가 페이지의 터치 처리와 같이 도는가. SwiftUI `scaleEffect` 아래에서 `location(in: webView)` 가 CSS 좌표와 맞는가(37 에서 탭 좌표는 맞았다).
7. **진짜 마우스.** iPad 시뮬레이터에서 맥의 포인터를 기기로 넘겼을 때(시뮬레이터 메뉴의 Send Pointer to Device) `pointerType` 이 `mouse` 로 오고 가리키기·클릭이 변환 없이 되는가. 되지 않으면 "하지 못함"으로 적는다(실기기는 사용자가 확인).
8. **터치 감지를 하는 엔진 코드.** `'ontouchstart' in window` 로 터치를 켜는 코드(Phaser 식)가 지금 어떻게 판단하는가. §2.5 의 두 방법이 각각 듣는지.

## 2. 터치 → 마우스 변환

### 2.1 한 손가락 = 왼쪽 단추

한 번에 한 손가락만 마우스다. 처음엔 닿은 손가락이고, 누르고 있는 중에 다른 손가락이 닿으면 새 손가락이 마우스가 된다(아래 "두 번째 손가락"). 좌표는 CSS 좌표(`clientX`·`clientY`) 그대로.

| 손가락 | 보내는 것 |
|---|---|
| **닿음** | ① 가리키기 옮김(§2.2) ② `mousedown`(button 0, buttons 1, `detail` = 연타 수) |
| **움직임** | `mousemove`(buttons 1). 아래 요소가 바뀌면 가리키기 옮김. 처음 자리에서 한계(화면 기준 10pt, CSS 로는 `10 ÷ 배율`)를 넘으면 이 터치는 **끌기** |
| **가만히 0.45초** | 끌기가 아니면 이 터치는 **가리키기**. 약한 진동 한 번(네이티브에 알림, 패드 진동 설정이 꺼져 있으면 안 울림), `title` 말풍선(§4) |
| **뗌** | `mouseup`. 끌기도 가리키기도 아니면 `click`(대상은 down 대상과 up 대상의 공통 조상), 연타 두 번째면 `dblclick`. 그 뒤 가리키기 나감(§2.2) |
| **취소** (`pointercancel`, 스크롤 시작) | `mouseup` 만. `click` 없음. 가리키기 나감 |

- 즉 **짧게 누르면 클릭, 길게 누르면 가리키기만(떼도 클릭 안 됨), 누른 채 움직이면 끌기**다.
- **두 번째 손가락**(거리·시간 조건 없음): 누르고 있는 중에 다른 손가락이 닿으면 앞 손가락의 누름을 그 자리에서 끝낸다. `mouseup`, 그리고 탭 조건(끌기도 가리키기도 아님)을 채웠으면 `click`(연타면 `dblclick`)까지. 앞 손가락이 끌던 중이었으면 `mouseup` 만. 그 뒤 새 손가락이 마우스가 되어 새로 `mousedown` 부터 시작한다. 앞 손가락을 떼거나 움직여도 마우스 이벤트는 더 보내지 않는다. 두 엄지로 번갈아 빨리 눌러도 탭이 사라지면 안 된다. 진짜 포인터·터치 이벤트는 손가락마다 그대로 게임에 간다(빙수가 막거나 해석하지 않는다).
- 실시간이다. `mousedown` 은 닿는 순간, `mousemove` 는 움직일 때마다 보낸다(WebKit 처럼 떼고 나서 몰아서 보내지 않는다). `mousedown`·`mousemove`·`mouseup` 으로 끌기를 만든 게임이 손가락으로 되어야 한다.
- 연타: 직전 `click` 과 같은 자리(한계 안), 0.4초 안이면 `detail` 을 1 올린다. `detail` 이 2 가 될 때 `dblclick`. 3 이상에서는 `dblclick` 을 내지 않는다(PC 규칙).
- 이벤트 속성은 PC 처럼 채운다: `bubbles`·`cancelable`·`composed`·`view`, `screenX/Y`, `movementX/Y`, `relatedTarget`, 보조키는 전부 거짓. `mouseenter`·`mouseleave` 는 버블링하지 않는다.
- `PointerEvent` 는 만들지 않는다(진짜가 이미 간다).
- 포커스: 입력 칸에 포커스가 있을 때 다른 곳을 누르면 `blur` 시켜 키보드를 내린다.
- WebKit 이 탭 뒤에 만드는 마우스 이벤트는 0단계 1번의 방법으로 막는다. 그렇지 않으면 게임이 클릭을 두 번 받는다.
- 주 프레임만 다룬다. `iframe` 안은 WebKit 기본 동작에 맡기고 기록한다.

### 2.2 가리키기 (hover)

"지금 가리키는 요소" 하나를 변환기가 기억한다.

- 옮길 때: 옛 요소에 `mouseout`, 옛 쪽에만 있는 조상들에 `mouseleave`(안쪽부터), 새 요소에 `mouseover`, 새 쪽에만 있는 조상들에 `mouseenter`(바깥부터), 그리고 `mousemove`. PC 순서와 같게.
- 나갈 때: 가리키던 요소에 `mouseout`, 그 요소와 조상 전부에 `mouseleave`. 가리키는 요소는 없음이 된다.
- 손가락을 떼면 나간다(기본). 탭이든 길게 누르기든 같다. 설명 창이 손을 뗀 뒤에 남지 않게 하려는 것이다.
- 진짜 마우스의 가리키기도 같은 기억에 반영한다(§3 의 표시를 붙이려고). 이벤트는 만들지 않고 듣기만 한다.

### 2.3 페이지가 터치를 직접 처리하는 경우

PC 브라우저·모바일 브라우저 규칙을 그대로 따른다.

- 페이지가 `touchstart` 나 `touchend` 에서 `preventDefault` 를 했으면 그 터치에는 마우스 이벤트를 만들지 않는다(터치를 직접 처리하는 게임이 입력을 두 번 받지 않게).
- 페이지가 `pointerdown` 에서 `preventDefault` 를 했으면 그 터치의 `mousedown`·`mousemove`·`mouseup` 은 만들지 않고 `click` 만 만든다.
- 페이지의 처리기가 다 돈 뒤에 판단해야 하므로, `mousedown` 은 `pointerdown`·`touchstart` 가 다 전달된 직후(같은 프레임 안)에 보낸다. 방법은 0단계에서 정한다. 지연은 한 프레임을 넘지 않게.

### 2.4 그대로 두는 요소 (통과 목록)

아래 요소에서 시작한 터치는 변환하지 않고, WebKit 이 만드는 이벤트도 막지 않는다. 키보드·선택기·조절 막대는 진짜 사용자 동작이어야 뜬다.

- `input`(checkbox·radio·button·submit·reset·image 제외), `textarea`, `select`, `[contenteditable]`, `video[controls]`, `audio[controls]`

체크박스·라디오·단추·링크·`label` 은 직접 만든 `click` 으로 동작한다(기본 동작이 실행된다). 두 번 실행되지 않는지 시험용 화면에서 확인한다.

### 2.5 "터치 기기"로 보이지 않게

37 은 로컬 게임에 `maxTouchPoints = 0` 과 `matchMedia` 흉내를 넣는다. 그런데 `'ontouchstart' in window` 는 여전히 참이라, 터치와 마우스를 둘 다 듣는 엔진은 입력을 두 번 받을 수 있다.

- 필수: §2.3 의 `preventDefault` 규칙.
- 권장(0단계 8번에서 해가 없으면): 이 계층이 켜진 게임에서는 `ontouchstart`·`ontouchmove`·`ontouchend`·`ontouchcancel` 속성을 감춰 `'ontouchstart' in window`·`in document.documentElement` 가 거짓이 되게 한다. 이벤트 자체는 그대로 흐른다.

## 3. CSS `:hover`

직접 만든 마우스 이벤트로는 CSS 의 `:hover` 가 켜지지 않는다. 그리고 WebKit 은 탭한 요소에 `:hover` 를 붙인 채 다음 탭까지 남겨 둔다(강조가 남아 보인다).

- 스타일 규칙의 선택자에서 `:hover` 를 표시 속성(예 `[data-bingsu-hover]`)으로 **바꿔 넣는다**. 변환기는 가리키는 요소와 그 조상 전부에 이 속성을 붙이고, 나가면 뗀다. 진짜 마우스로 가리킬 때도 같은 속성을 붙이므로 트랙패드에서도 그대로 보인다.
- 대상: 같은 출처의 스타일시트 전부. `@media`·`@supports`·`@layer` 안까지. 나중에 더해지는 `<style>`·`<link>` 도(`MutationObserver` + `load`).
- 선택자를 바꿔 넣지 못하는 규칙(대입이 거부됨)은 그대로 두고 수를 로그에 남긴다. `insertRule` 로 실행 중에 더해지는 규칙, `adoptedStyleSheets`, 인라인 `style` 은 하지 못해도 된다(기록).
- 후순위: `@media (hover: hover)`·`(pointer: fine)` 처럼 "마우스가 있는 기기" 조건 안의 규칙이 iPhone 에서 꺼지는 문제. JS 의 `matchMedia` 는 37 이 이미 흉내 낸다. CSS 쪽은 시험용 화면으로 영향을 재고, 고치기 쉬우면 고치고 아니면 기록한다.

## 4. `title` 설명 (말풍선)

PC 브라우저는 `title` 속성을 마우스를 올리면 작은 설명으로 보여 준다. iOS 는 보여 주지 않는다. 운빨던전은 `title` 을 40곳 넘게 쓴다(HTML 에 36곳, 스크립트로 넣는 것 11곳).

- 터치가 "가리키기"가 된 순간(§2.1), 닿은 요소에서 가장 가까운 `title` 있는 조상을 찾아 그 글을 말풍선으로 띄운다. 손가락을 떼거나 움직여 다른 요소로 가면 없앤다.
- 손가락에 가리지 않게 요소 위쪽에(자리가 없으면 아래쪽), 화면 밖으로 나가지 않게 둔다.
- 글자는 `textContent` 로만 넣는다(HTML 로 해석하지 않는다). 최대 300자, 줄바꿈 유지.
- 게임 화면이 줄어 있으므로(배율 0.3~0.7) 글자가 실제 화면에서 13pt 쯤으로 보이게 배율로 보정한다. 네이티브가 지금 배율을 스크립트에 알려 준다.
- 권장 구현: 페이지 안, 닫힌 shadow root 의 `position: fixed` 요소(`pointer-events: none`, 가장 위). 게임의 CSS·스크립트가 건드리지 못하게. 빙수의 밝은·어두운 색을 따른다.
- 진짜 마우스에서는 0.6초 가만히 있으면 같은 말풍선을 띄운다.

## 5. 두 손가락 — 하지 않음

사용자 결정(2026-11-11)으로 지웠다. 두 손가락 탭 = 오른쪽 클릭, 두 손가락 끌기 = 휠을 만들지 않고, 네이티브 두 손가락 인식기도 없다. 두 손가락 터치는 해석하지 않고 손가락마다 게임에 그대로 간다(마우스는 §2.1 의 "두 번째 손가락" 규칙). 진짜 마우스·트랙패드의 오른쪽 클릭·휠은 지금처럼 그대로 간다. 필요한 게임이 나오면 따로 넣는다(§13).

## 6. 확대 — 하지 않음

사용자 결정(2026-11-11)으로 지웠다. 벌리기 확대, 확대 중 이동, "원래 크기" 단추가 없다. 게임 화면은 줄여 그린 그대로이고, `title` 말풍선(§4)만 그 배율에 맞춰 읽을 크기로 띄운다.

## 7. 키보드 키 줄

PC 게임은 키 몇 개를 쓴다(운빨던전: Esc 로 닫기, Enter, Space, 도감의 ←·→). 화면에 작은 키를 띄운다.

- **어떤 키:** 판별(§10)이 찾은 키. 최대 6개, 순서는 Esc → Enter → Space → 방향키 → 그 밖. 찾은 것이 없거나 예전에 가져온 게임(`keys` 없음)이면 Esc·Enter·Space.
- **어디에:** 게임 화면 밖 빈 띠에 둔다. 가로에서 양옆 띠가 있으면 한쪽에 세로로, 위아래 띠가 있으면(iPad) 아래에 가로로, 세로 화면이면 게임 아래. 띠가 44pt 보다 좁으면 게임 가장자리에 겹쳐 반투명하게. 눈송이 단추와 겹치지 않는다. 자리 계산은 순수 함수로 만들어 자가 테스트한다.
- **모양:** 36~40pt 둥근 사각, 글자는 `Esc`·`Enter`·`Space`·`←` 식. 투명도와 진동은 가상 패드 설정을 따른다.
- **동작:** 누르면 `keydown`, 떼면 `keyup`. 지금 가상 패드가 쓰는 길(`__bingsu.key(code, down)`)로 보낸다. 그 표(`KEYS`)에 없는 키는 표를 넓힌다(글자·숫자·F1~F12·Tab·Backspace 는 규칙으로 계산). 누르고 있으면 0.4초 뒤부터 PC 처럼 `repeat` 인 `keydown` 을 되풀이한다.
- **언제 보이나:** 조작 방식이 터치이고 키가 하나라도 있으면 처음부터. 가상 패드가 보이는 동안과 키보드(블루투스 등)가 연결돼 있으면 숨긴다. 일시정지 화면과 이 게임 설정에서 끄고 켠다(§8).
- 글자 입력용 키보드가 아니다. 입력 칸은 iOS 키보드가 뜬다(§2.4).

## 8. 방식 고르기 · 설정 · 화면

- **게임별 설정에 "조작" 묶음**(`DishSettingsView`, 새 모양 Electron 게임에만 보임):
  - "조작 방식": 자동(지금 고른 것을 괄호로) / 터치 / 가상 패드. `DishPrefs.inputStyle`(nil = 자동 = 판별 결과). 게임을 다시 켜면 적용된다는 안내.
  - "키보드 키 보기": 켬/끔. `DishPrefs.keyStrip`(nil = 자동, §7).
  - 묶음 아래 한 줄 설명: "길게 누르면 설명이 보여요" 정도. 문구는 사용자가 나중에 고칠 수 있다.
- **일시정지 화면**(`PauseBoard`): 지금 있는 "가상 패드" 스위치 옆에 "키보드 키" 스위치. 포커스 이동(`PauseItem`) 순서에도 넣는다.
- **세로 안내:** iPhone 에서 터치 방식 게임을 세로로 열면 한 번 "가로로 돌리면 크게 보여요" 를 띄운다(지금 있는 토스트, 게임을 켤 때마다 한 번).
- **패드 방식인 새 모양 게임:** 37 에서 확인하지 못했다. `BINGSU_FORCE_PAD=1` 로 `electron-plain` 의 가상 패드가 보이고 키가 들어가는지 확인한다.
- 가상 패드를 켠 채로도 게임 화면의 터치는 마우스로 간다(패드 단추 위는 패드가 받는다).

## 9. HTML 끌어다 놓기 (후순위)

`draggable="true"` 와 `dragstart`·`dragover`·`drop` 을 쓰는 게임. iPhone 의 웹뷰는 이것을 하지 않고, iPad 는 길게 눌러야 해서 §2 의 가리키기와 부딪친다.

- 한 손가락 끌기(§2.1)가 `draggable="true"` 요소에서 시작됐으면: `dragstart`(가짜 `DataTransfer`: `setData`·`getData`·`types`·`effectAllowed`·`dropEffect`·`setDragImage`) → 움직이는 동안 `drag`, 손가락 아래 요소에 `dragenter`·`dragover`·`dragleave` → 뗄 때 마지막 `dragover` 가 `preventDefault` 됐으면 `drop` → `dragend`. 끄는 동안 요소의 반투명 복제본이 손가락을 따라간다.
- `dragstart` 가 `preventDefault` 되면 끌어다 놓기는 시작하지 않고 보통 마우스 끌기로 남는다(운빨던전은 `dragstart` 를 막는다).
- 앞 단계가 다 끝난 뒤에 한다. 하지 못하면 "구현 기록"에 적고 다음 단계로 넘긴다.

같은 후순위: **가리키기 남겨 두기.** 마우스를 올리면 열리는 메뉴(올린 채로 안쪽 항목을 눌러야 하는 것)는 "떼면 나감"으로는 쓸 수 없다. 게임별 설정에 "누른 설명 남겨 두기" 스위치(켜면 길게 누른 뒤의 가리키기가 다음 터치까지 남음)를 두는 안이다. 시험용 화면에 이런 메뉴를 넣어 실제로 막히는지 먼저 확인한다.

## 10. 판별 보강 (`RedBeanProbe`)

- 화면 쪽 코드에서 게임이 듣는 키를 모은다: `e.key === '…'`·`event.key == "…"`·`.code === '…'`·`keyCode === 숫자`·`which === 숫자`, 그리고 `keydown`·`keyup` 듣기가 있는 파일 안의 `case '…':`. 아는 키 이름표에 있는 것만 받는다. 많이 나온 순으로 최대 12개를 `ElectronInfo.keys`(`KeyboardEvent.code` 글자)로 적는다.
- `bingsu.json` 의 `electron.keys` 로 읽고 쓴다. 읽을 때 아는 이름만 남긴다(파일은 믿지 않는다).
- 조작 방식 규칙(`!gamepad && pointer > 0 && keys * 5 <= pointer`)은 바꾸지 않는다. 운빨던전은 지금처럼 터치로 판정돼야 한다.
- 가져오기 로그에 `keys=[Escape,Enter,…]` 를 더한다.

## 11. 시험용 화면 (`tools/compat-fixtures/touch-lab/`)

실제 게임은 커밋할 수 없으므로 직접 만든 Electron 식 작은 앱 하나(`package.json` + 메인 + 화면, 1280×720). 한 화면에 칸을 나누고, 칸마다 받은 이벤트를 화면과 `console.warn("[fixture] …")` 로 남긴다.

1. `click` 횟수. 한 번 탭 = 정확히 1.
2. `mouseenter` 에서 화면을 바꾸는 단추(첫 탭 버릇 확인). 한 번 탭 = `click` 1.
3. `mouseenter`·`mouseleave` 로 뜨는 설명 창, `mouseover`·`mouseout` 위임 방식 하나.
4. `:hover` 로 색이 바뀌는 단추, `:hover` 로 열리는 메뉴(안쪽 항목에 `click`), `@media (hover: hover)` 안의 규칙.
5. `title` 설명.
6. `mousedown`·`mousemove`·`mouseup` 만으로 만든 끌기(상자 옮기기).
7. 포인터 이벤트 + `setPointerCapture` 로 만든 끌기(운빨던전 방식), `touch-action: none`.
8. `dblclick`, `detail` 값 표시.
9. 진짜 마우스·트랙패드 확인용: `contextmenu`, `mousedown` 의 `button`, 값을 받아 `preventDefault` 하는 `wheel`, 그냥 `overflow: auto` 인 긴 목록. 손가락으로는 아무것도 만들지 않는다(§5).
10. 양손 번갈아 빨리 누르기: 양쪽 끝 단추 둘, 누른 수와 `click` 수(§2.1 두 번째 손가락).
11. `keydown`·`keyup` 표시(`key`·`code`·`repeat`), Esc 로 닫히는 창.
12. `input`·`textarea`·`select`·checkbox·`label`·링크.
13. `draggable="true"` → 놓는 자리(§9).
14. 터치를 직접 듣고 `preventDefault` 하는 칸(§2.3), `'ontouchstart' in window` 값 표시(§2.5).
15. 작은 글씨 줄과 작은 단추(8px).

같은 화면을 맥의 Chrome·Safari 에서 열어 PC 의 정답(이벤트 순서, `detail`)을 "구현 기록"에 적어 둔다.

자가 테스트(`StrawSelfTest`)는 순수 함수만 본다: 키 고르기·순서, 키 줄 자리 계산, 판별의 키 모으기(위 폴더를 읽은 결과 포함), `DishPrefs` 예전 파일 읽기. 변환기 자체는 §12 에서 손과 시뮬레이터 도구로 확인한다. DEBUG 빌드에서만 켜지는 스위치로 시험용 화면이 가짜 터치 순서를 흘려 변환기를 자동으로 시험하게 만들면 더 좋다(Release 에 들어가면 안 된다. 변환기는 평소 `isTrusted` 인 터치만 듣는다).

## 13. 하지 않는 것

- 컨트롤러를 마우스로 쓰기(왼스틱 = 커서). 나중.
- 일반 NW.js 게임, preload 방식 다듬기, 호환 보고서 화면, 게임별 보정 파일, 37 기록의 대화상자 단추 글자·쓰기 한도 캐시 → 다음 단계(웹 계열 3차).

- 운빨던전 자체의 조작 방식 바꾸기(끌기 거리 등은 게임의 것이다).
- Ctrl+휠, 가운데 단추, 마우스 가두기(`requestPointerLock`), 키 조합(Ctrl+S 등).
- 화면에 커서 그리기.
- **오른쪽 클릭, 휠, 확대는 하지 않는다. 필요한 게임이 나오면 따로 넣는다.** (사용자 결정 2026-11-11, §5·§6)
- **빌드 번호, "새로운 기능" 글, TestFlight 아카이브·업로드, main 병합, 푸시, 사이트 글.** 전부 사용자 결정 뒤에 한다. 38 의 "새로운 기능" 글은 사용자가 정한다.

### 0단계 결과 (2026-11-11, iPhone 17 Pro 시뮬레이터 가로, 시험용 화면 `touch-lab`)

PC 정답은 맥의 Chromium(앱 안 브라우저, 1280×720)에서 같은 화면을 열어 얻었다.

- PC 클릭 순서: `pointerover` `pointerenter` `mouseover` `mouseenter` `pointerdown` `mousedown`(detail 1) `pointerup` `mouseup` `click`(PointerEvent, pointerType mouse), 나갈 때 `pointerout` `pointerleave` `mouseout` `mouseleave`. 두 번 누르기: `click` d1 → `mousedown` d2 → `click` d2 → `dblclick` d2. checkbox·label: 한 번에 `click` 1·`change` 1.
- PC 오른쪽 클릭(맥): `pointerdown` → `mousedown`(button 2, buttons 2) → `contextmenu` → `pointerup` → `mouseup`. 명세 §5 는 윈도 순서(`mouseup` 뒤 `contextmenu`)라서 그대로 두었다. 게임 대부분은 윈도에서 만들어진다.

WebKit 그대로(변환 없음):

- 탭 한 번: `pointerover` `pointerenter` `pointerdown` `touchstart` … `pointerup` `pointerout` `pointerleave` `touchend`, 그 뒤 5~70ms 지나 `mouseover` `mouseenter` `mousemove` `mousedown`(buttons 0) `mouseup` `click` 이 한꺼번에 온다. 가리키기가 다음 탭까지 남는다(`mouseout` 없음).
- `mouseenter` 에서 화면을 바꾸는 단추(칸 2): iOS 26 시뮬레이터에서는 첫 탭에 `click` 이 왔다. "첫 탭은 가리키기만" 버릇은 이 칸으로는 다시 만들어지지 않았다(운빨던전 보고는 실기기·다른 상황일 수 있다).
- 끌면 손을 뗀 뒤 **처음 닿은 자리**에 마우스 이벤트 묶음과 `click` 이 온다. `mousedown`·`mousemove`·`mouseup` 만으로 만든 끌기(칸 6)는 움직임 0. 포인터 이벤트 + `setPointerCapture` 끌기(칸 7)는 된다.
- 길게 누르면 마우스 이벤트가 아예 없다. `'ontouchstart' in window` 는 참, CSS `@media (hover: hover)` 는 거짓(JS `matchMedia` 흉내는 참이라 둘이 어긋남).

여덟 가지:

1. **WebKit 의 탭 뒤 마우스 이벤트 막기 — 된다.** `window` capture 에서 `isTrusted` 이고 직전 포인터가 touch·pen 인 `mouseover`/`out`/`enter`/`leave`/`move`/`down`/`up`/`click`/`dblclick`/`contextmenu` 를 `stopImmediatePropagation` 하면 페이지는 빙수가 만든 것(`isTrusted` 거짓)만 본다. 칸 1 기록: `mouseover* mouseenter* mousemove* mousedown*(1) mouseup*(1) click*(1) mouseout* mouseleave*`, 한 번 탭 = click 1. 대비책(`touchend` 의 `preventDefault`)은 쓰지 않았다. 단, 키보드 입력 `click`(detail 0)은 막지 않는다.
2. **직접 만든 click 안의 사용자 동작 — 처음엔 안 됐고 고쳐서 된다.** `MessageChannel` 로 미룬 작업에서 보낸 click 안에서는 `clipboard.writeText` 가 `NotAllowedError`. 그래서 `mousedown` 은 `touchstart`, `mouseup`·`click` 은 `touchend` 의 **window 버블 단계 처리기 안에서 바로** 보낸다(페이지 처리기가 다 돈 뒤라 §2.3 의 `preventDefault` 판단도 할 수 있다). 페이지가 `stopPropagation` 해서 버블이 안 오면 그때만 미룬 작업으로 보낸다. 결과: `audio.play()` 됨, 복사 됨, `<input type=file>.click()` 은 iOS 고르기 메뉴가 뜸, 바깥 링크는 37 의 "사파리에서 열까요?" 대화상자가 한 번 뜸.
3. **입력 칸 — 된다.** 통과 목록 요소를 탭하면 키보드가 뜨고 한글이 입력된다. 키보드가 뜨면 `innerHeight` 720 → 423 으로 줄고 화면이 위로 밀린다. 다른 곳을 탭하면 `blur` 되고 돌아온다. `<select>` 는 iOS 고르기 메뉴. checkbox 는 한 번 탭에 `click` 1·`change` 1(두 번 바뀌지 않음).
4. **안쪽 스크롤 — 된다.** `overflow: auto` 목록이 한 손가락으로 스크롤된다. 스크롤이 시작되면 `pointercancel` 이 오고, 빙수는 그때 `mouseup` 만 보내고 `click` 은 보내지 않는다.
5. **길게 누를 때 iOS 끼어듦 — 없음.** 37 의 `fullscreenCSS` 가 새 모양 게임에도 들어가 있어 글자 선택·돋보기·콜아웃이 뜨지 않았다. 링크를 길게 눌러도 미리보기가 없고 click 도 없다. iPad 의 그림 끌어올리기는 §12 의 iPad 확인에서 본다.
6. **네이티브 제스처 인식기 — 같이 돈다.** (지우기 전 결과. 지금은 인식기가 없다) 웹뷰에 붙인 두 손가락 핀치·끌기·탭(`cancelsTouchesInView = false`, 동시 인식 허용)과 페이지 터치 처리가 함께 돈다. 인식기가 터치를 취소하지 않으므로 두 번째 손가락이 닿는 순간 빙수가 첫 손가락 처리를 취소하고 페이지의 첫 손가락 포인터에 `pointercancel` 을 직접 보낸 뒤, 손가락을 다 뗄 때까지 손가락의 포인터·터치 이벤트를 페이지에 보내지 않는다. `scaleEffect` 아래(37 맞춤 배율과 4배 확대 모두)에서 탭 좌표가 CSS 좌표와 맞았다(4배에서 "창 열기" 가운데 677,409 를 676,408 로 받음).
7. **진짜 마우스 — 하지 못함.** 시뮬레이터 제어 도구로는 맥의 포인터를 기기로 넘길 수 없다. 코드는 `pointerType` 이 `mouse` 면 변환하지 않고, 진짜 `mouseover`·`mouseout` 으로 가리키는 요소를 따라가 0.6초 뒤 `title` 말풍선만 띄운다. 실기기(iPad + 마우스·트랙패드)에서 확인할 것.
8. **터치 감지 코드 — 숨기면 듣는다.** 그대로는 `'ontouchstart' in window` 참. `window`·`Window.prototype`·`Document.prototype`·`HTMLElement.prototype`·`Element.prototype`·`SVGElement.prototype` 의 `ontouch*` 속성을 지우면 `window`·`document.documentElement` 둘 다 거짓이 된다(§2.5 첫 방법). `maxTouchPoints` 는 37 부터 0. `TouchEvent` 생성자는 남겨 두었다(지우면 WebKit 안쪽이 깨질 수 있다). `@media (hover: hover)`·`(pointer: fine)` 은 CSS 규칙을 다시 써서 맞춘다(§3).

### 명세와 다르게 한 것

- **마우스 이벤트를 보내는 때(§2.1):** 미룬 작업이 아니라 `touchstart`·`touchend` 의 window 버블 단계 처리기 안에서 바로 보낸다. 미룬 작업 안의 click 에서는 복사·소리 같은 사용자 동작이 막혔기 때문(0단계 2번).
- **`touchend` 만 막은 경우(§2.3):** `touchstart` 를 막았으면 마우스 이벤트를 하나도 안 보내지만, `touchend` 만 막았으면 이미 보낸 `mousedown` 의 짝인 `mouseup` 은 보내고 `click` 은 보내지 않는다. 눌린 채 남는 단추를 막으려고.
- **`@media (hover: hover)`·`(pointer: fine)`:** JS 흉내만으로는 CSS 가 어긋나서 그 규칙을 다시 써서 늘 맞게 했다(§3 과 함께).
- **"도착" `mousemove`:** 페이지가 `pointerdown` 을 막았어도 닿는 순간의 `mousemove`(buttons 0) 하나는 보낸다(운빨던전 확인 참고).
- **놓친 `pointerup`:** 두 번째 손가락 규칙에 없는 경우라, 첫 손가락(`isPrimary`)이 닿았는데 앞 손가락이 뗀 기록 없이 남아 있으면 `click` 없이 버린다(위 "사용자 결정으로 줄인 것").
- **가져오기 로그:** `Delivery` 의 가져오기 줄에 `keys=N [Escape,Enter,…]` 를 붙였다.
- **커밋 단위:** §14 의 2~4단계(변환, `:hover`·`title`, 두 손가락·확대)는 같은 스크립트·제스처 파일을 함께 고쳐서 한 커밋으로 묶었다. 두 손가락·확대를 지운 것은 따로 한 커밋.

### 하지 못한 것

- §9 (HTML 끌어다 놓기, "가리키기 남겨 두기") — 후순위라 하지 않았다. 시험용 화면 칸 13 과 칸 4 의 `:hover` 메뉴 안 항목 누르기가 이것을 기다린다.
- 진짜 마우스·트랙패드(iPad) — 시뮬레이터로는 못 함.
- 두 번 눌러 공격이 가끔 안 나가는 것의 PC 나란히 비교.
- 끌던 손가락에 다른 손가락이 닿는 경우(시뮬레이터 도구로 못 만듦).
- 줄인 뒤 iPad 는 다시 보지 않았다(바뀐 것은 키 줄이 "원래 크기" 자리를 피하지 않게 된 것뿐이고, iPad 키 줄은 아래 띠라 그 자리와 겹치지 않았다).

### 실기기에서 볼 것

- 진동(키 줄 누를 때 가벼운 진동), 손가락 느낌(길게 누르기 0.45초 판정). 두 엄지로 번갈아 빨리 눌러 탭이 빠지지 않는지, 끌던 손가락에 다른 손가락이 닿으면 `click` 없이 끝나는지(시험용 화면 칸 10·칸 6).
- iPad + 마우스·트랙패드: 가리키기·클릭·`:hover`·`title` 말풍선(0.6초).
- 운빨던전 두 번 눌러 공격을 손으로 연달아 했을 때 빠지는지.
- 블루투스 키보드를 붙이면 키 줄이 숨고 떼면 돌아오는지.
- 운빨던전 "첫 탭이 가리키기로만 먹힘" 보고(37)가 실기기에서 다시 나는지.
